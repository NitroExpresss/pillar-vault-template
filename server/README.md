# Бэкенд хранилища (Go)

Одна задача: карточки не уходят в браузер без пароля. Проверка живёт на
сервере, поэтому её нельзя обойти из консоли. Публичной части нет: без сессии
наружу не уходит ни одна карточка.

Страницы собирает сервер и отдаёт готовым HTML (`viewer/templates/`). Модель
хранилища живёт в памяти процесса и в браузер не уходит вовсе — ни списком
карточек, ни их текстами.

## Как устроено

| Путь | Кто пускает | Что отдаёт |
|---|---|---|
| `GET /` | все | по сессии — дашборд, без сессии — форма входа |
| `GET /doc/<id>` | по сессии | страница карточки: разметка, связи, показания |
| `GET /folder/<путь>`, `GET /tag/<тег>` | по сессии | списки карточек |
| `GET /search?q=` | по сессии | поиск (считает сервер, тексты в браузер не едут) |
| `GET /edit/<id>` | по сессии | форма правки; `POST` туда же сохраняет — если карточка изменилась на диске, пока редактор был открыт, не пишет, а показывает обе версии |
| `POST /vow` | по сессии | отметка столпа в `pillars/daily-vows.md` |
| `POST /diary` | по сессии | запись в конец `notes/diary.md` |
| `POST /today` | по сессии | день в `tasks/day.md`: `do=add` из общего списка, `new` своё, `done` закрыть (в исходной карточке), `remove` убрать из дня |
| `GET /today.json`, `GET /calendar.json?cal=ГГГГ-ММ`, `GET /body.json` | по сессии | данные виджетов Android: дела дня, месяц с метками, вес и путь к цели — единственные ответы не страницей (401 без сессии) |
| `POST /plan` | по сессии | «+ дело на этот день» из календаря: `- [ ] дело @дата` в `tasks/backlog.md`, раздел «По датам 📅» |
| `POST /metric` | по сессии | «+ замер» (дашборд и виджет «Тело»): строка за дату в таблицу карточки `metrics: body`, та же дата — замена; `do=cleardemo` — убрать демо-строки (первая остаётся) |
| `GET/POST /api/new` | по сессии | новая карточка из приложения: GET — разделы, типы, дерево тем; POST (с `X-Pillar-Api`) — создать: frontmatter собирает сервер по уставу |
| `GET /api/inbox`, `POST /inbox` | по сессии | входящие: мысли из «Захвата» по разделам; `do=task` — в бэклог делом, `do=remove` — убрать (после «В карточку» — тоже) |
| `GET /api/health` | по сессии | здоровье хранилища: ошибки и предупреждения линтера по карточкам (тот же `-lint`, что в CI); пересчёт — после пересборки хранилища |
| `GET /api/connections`, `POST /connections` | по сессии | подключения к LLM-провайдерам (Grok, OpenAI-совместимые, локальный шлюз): `do=add` (preset, key), `do=remove`, `do=test` (без `prompt` — ключ и список моделей, с `prompt` — ответ модели); ключи — `server/.connections.json` (0600, вне git) |
| `POST /pin` | по сессии | закрепить (`on=1`) или открепить карточку в «Важном» — строка `pin: true` во frontmatter |
| `POST /archive` | по сессии | в архив (`on=1`: `status: archived`, закрепление снимается — карточка уходит из поиска и «Важного», остаётся в разделе) или обратно (`on=0`: `draft`) |
| `POST /goal` | по сессии | цель без markdown: `do=value` — показания за дату (`v<колонка>`), `do=deadline` — срок (пусто — снять), `do=kr` — новый результат (name, unit, target) |
| `POST /capture` | по сессии | мысль из «Захвата» — в `inbox/capture-ideas` (ссылка — в раздел ссылок) |
| `GET /pins.json`, `/burn.json`, `/goals.json` | по сессии | виджеты «Важное», «Что горит» (вкладка «Сегодня»), «Цели» |
| `GET /day.json?date=` | по сессии | окно дня виджета «Календарь»: дела, столпы, замеры, дневник |
| `POST /task` | по сессии | «Учёт дел»: `do=done` закрыть дело в его карточке (и убрать из дня), `open` открыть снова |
| `POST /gallery` | по сессии | фото и подписи витрины: `do=save` (слайд или `slot=new`), `remove`; только картинки, до 4 МБ |
| `POST /login`, `POST /logout` | все | вход формой и выход |
| остальное | все | статика из `viewer/`; гостю — только стили, шрифты и скрипт |

Пароль хранится хэшем PBKDF2-HMAC-SHA256 (600 000 итераций, случайная соль),
сверка — в постоянном времени. Попытки входа ограничены: 10 за 15 минут с адреса.

Сессия — не запись в памяти, а подписанный билет «до-когда.подпись» на 7 дней; пока им пользуются, сервер раз в сутки выдаёт новый (`renewSession`);
ключ подписи выведен из хэша пароля. Отсюда три следствия: перезапуск службы
никого не разлогинивает, смена пароля рвёт все сессии сама, а отозвать одну
сессию досрочно нечем — только сменой пароля.

Без пароля войти нельзя вовсе: сервер поднимается и показывает форму входа,
за которой ничего нет.

## Запуск

```bash
go run ./server -root . -hash        # ввести пароль, получить строку хэша
go run ./server -root .              # пароль возьмётся из server/.passhash
```

Флаги: `-addr` (адрес), `-root` (корень хранилища), `-lint` (проверить
хранилище и выйти), `-hash` (посчитать хэш пароля), `-check` (сверить пароль
с настроенным хэшем), `-health` (проверка живости).

Модель хранилища собирается в память при старте и пересобирается на лету —
после правки через веб и при изменении файлов на диске. Файла сборки нет:
отдавать его нечем, забыть пересобрать нельзя.

Шаблоны страниц перечитываются тем же сторожем: правка вида не требует ни
пересборки бинаря, ни перезапуска службы.

Пароль берётся из `PILLAR_PASS_HASH`, иначе из файла `server/.passhash`.
Ни того, ни другого — вход отключён, и хранилище не отдаётся никому.

## На сервере

Прод — служба systemd, см. [`../deploy/DEPLOY.md`](../deploy/DEPLOY.md).
Коротко: `/opt/pillar-vault`, бинарь слушает `127.0.0.1:8080`, хэш пароля
лежит в `server/.passhash` (0600), снаружи стоит nginx с TLS
([`../deploy/nginx-pillar-vault.conf`](../deploy/nginx-pillar-vault.conf)).
Basic Auth поверх не нужен: пароль проверяет сам сервер.

Песочница — не контейнер, а директивы юнита: файловая система только для
чтения кроме самого хранилища, сеть — только петля, повысить права нечем.

```bash
cd /opt/pillar-vault
bash deploy/passwd.sh        # задать или сменить пароль
```

Node в стеке нет вовсе: линтер хранилища — это тот же бинарь с флагом `-lint`
(`server/lint.go`), обход и разбор frontmatter у него общие с индексатором.

## Смена пароля

Перезапуск не нужен: сервер следит за `server/.passhash` (раз в 3 секунды,
вместе с карточками) и подхватывает новый хэш сам. Пустой или битый файл
пароль не сбрасывает — остаётся прежний. Хэш из `PILLAR_PASS_HASH` не
следится: окружение меняется только перезапуском.

**С сайта** — страница «Доступ» (🔑 в шапке, `/access`): старый ключ, новый
дважды. Старый спрашивается и под сессией — забытый незакрытым телефон не
даёт сменить ключ. Это устройство остаётся внутри, остальные выходят.

**С терминала** — `deploy/passwd.sh`: считает хэш (тем же `-hash`), кладёт
`server/.passhash` с правами 0600 и ждёт, пока вход новым паролем выдаст
сессию. Не дождался — перезапускает службу (так было со старым бинарём);
не сошлось и после — возвращает прежний хэш.

Пароль читается с терминала: он не попадает ни в `argv`, ни в историю
оболочки. Сессии на всех устройствах закрываются сами: билет подписан
ключом, выведенным из хэша пароля, — новый хэш делает прежние билеты
мусором. Отдельного списка сессий на сервере нет и чистить нечего.

Вручную: `-hash` → строка в `server/.passhash` — и всё.

## Журнал входов

Каждый вход, неверный ключ, отбитая по счётчику попытка и смена пароля
пишутся в `server/.logins.log` (0600, вне git): время, адрес, итог, строка
браузера. Пароль туда не попадает ни в каком виде. Последние 50 записей —
на странице «Доступ». Файл держится сам: дорос до 512 КБ — обрезается до
последних 2000 строк. Те же события идут в `journalctl -u pillar-vault`
строкой `доступ: <адрес> — <итог>`.

## Чего пока нет

Регистрации и пользователей — владелец один. Отозвать одну сессию нельзя — только сменой пароля.

## Автокоммит правок с веба

С флажком `server/.autocommit` (или `PILLAR_AUTOCOMMIT=1`) каждая запись с веба —
дело, столп, дневник, правка карточки, фото витрины — сразу коммитится
(`server/sync.go`). Отправляет в GitHub `deploy/deploy.sh`: процессу сервера
сеть наружу закрыта. Локально флажка нет — разработческий запуск в чужой
репозиторий не коммитит.
